## 实跑 `main.py` 发现的 3 个 bug（都在本次新增的防护逻辑里）

实跑暴露了一个环境问题（本机 Python DNS 解析失效，见踩坑），但也顺带暴露出防护逻辑本身的 3 个真 bug —— 都是「加防护时引入的」而非原有问题。

### Bug A：熔断阈值=1 导致雪崩式级联失败（最严重）
- 现象：yfinance 在 23:43:55 因 DNS 故障失败**一次** → 熔断 600 秒 → 之后 UMC/PLTR/INTC/CRWV/AAPL/TSLA **全部被跳过**；而日志证明 yfinance 随后一直正常（23:59:33 PLTR 成功拿到 41 行）
- 根因：`FETCHER_CIRCUIT_THRESHOLD = 1` 把「瞬时网络抖动」误判为「数据源永久损坏」。单次 DNS 失败 / 代理断连就摘掉整个源
- 修复：阈值 1 → **3 次连续失败**，冷却 600s → **120s**，并支持 `FETCHER_CIRCUIT_THRESHOLD` / `FETCHER_CIRCUIT_COOLDOWN` 环境变量覆盖
- 实测验证：单次失败后 `is_circuit_open=False` 且恢复后正常取数；连续 3 次失败后 `is_circuit_open=True`（真坏源仍被熔断）

### Bug B：配额降级完全不生效
- 现象：日志 `优先级从 99 降至 99` —— 降级写了个没人再读的字段
- 根因：只改了 `fetcher.priority = 99`，但 `_get_fetchers_snapshot()` 返回的是**已排序列表的浅拷贝**，而排序只在 `__init__` / `add_fetcher` 里做，运行时改 priority 不重排列表
- 修复：抽出 `_demote_fetcher_priority()`，降级时在 `_fetchers_lock` 内 `self._fetchers.sort(key=lambda f: f.priority)`；并做幂等（已降级过则直接 return，避免重复刷日志）
- 实测：降级后顺序从 `[A,B,C]` 变为 `[B,C,A]`，耗尽源 `calls` 停在 1

### Bug C：通用 fetcher 循环（A 股/港股路径）缺护栏
- 现象：`LongbridgeFetcher` 未配置凭据，仍被港股通用循环调用，每只票刷一条 `QuoteContext not available`；连接型坏源也不会被熔断器记住
- 根因：美股/港股**专用路由**加了 `_is_fetcher_available` 过滤和熔断跳过，**通用循环**（`get_daily_data` 尾部）两样都没有，也没上报熔断状态
- 修复：通用循环补上凭据检查 + 熔断跳过，并在成功/失败分支接入 `_record_fetcher_success/_record_fetcher_failure`

### 踩坑记录（重要）
- 用 Edit 插入函数时，old_string 只匹配了 `def _persist_disabled_key(...)` 那一行签名，new_string 里忘了把签名行加回去 → 函数体错位成上一个函数的续行，表现为"某个 TestCase 全部 11 个用例失败"。**插入函数时应把完整签名包含在 new_string 中**
- 类级可变状态（黑名单/熔断表）会造成测试间污染，项目惯例是提供 `reset_*()` 类方法并在测试 setUp 调用（参考既有 `reset_public_instance_cache`）
- **写测试前先读实现，别照着自己记忆写预期**：曾把 `510300.SH`（A 股 ETF）写进「非 A 股跳过筹码分布」的参数化用例，实际 `normalize_stock_code` 会把它归一化成 6 位数字正常走数据源链路 —— 代码是对的，测试写错了
- `get_main_indices()` 全部源失败时返回 **`[]` 而非 `None`**（既有契约），断言要写 `assert not result`
- **`scripts/ci_gate.sh` 必须先 `export PATH="/Users/css/miniconda3/bin:$PATH"`**，否则走系统 python 报 `No module named 'pandas'` 直接挂在第一步，看着像代码挂了其实是环境问题
- 仓库 flake8 配置只 ignore `E501,W503,E203,E402`，CI gate 只跑 `--select=E9,F63,F7,F82` 严重级；`base.py` 里存量大量 `W293 blank line contains whitespace`，**不要顺手清理**，与本次任务无关且会制造大 diff
- **Edit 替换类常量块时容易连带删掉邻近常量**：把 `FETCHER_CIRCUIT_THRESHOLD/COOLDOWN` 提到模块级时，一度把 `FETCHER_CALL_TIMEOUT_SECONDS` / `YFINANCE_TICKER_TIMEOUT_SECONDS` 覆盖掉了。**改动 base.py 顶部常量区后要立刻 `python -c "import ...; print(常量)"` 复核四个值都在**
- 改熔断阈值会让依赖「阈值=1」的旧用例失败（`test_circuit_expires_after_cooldown` 等）。**测试里不要硬编码阈值，用 `manager.FETCHER_CIRCUIT_THRESHOLD` 循环**，否则调参就得改测试
- **本机 Python DNS 解析失效（2026-10-07 23:50 前后出现）**：`socket.gethostbyname` / `getaddrinfo` 对所有域名返回 `Errno 8`，但 `host` / `nslookup` / `dig` 均正常，miniconda 与系统 python 都一样 → 是 `mDNSResponder` 层面的问题，不是项目代码。此时项目里 akshare / 东财 / 新浪 / Tushare 全部 `NameResolutionError`，只有 yfinance（走代理）能用。修复需 sudo 重启系统 DNS 服务，**Python 代码层无解**，排查时先用 `host <域名>` 对照区分「代码 bug」还是「网络故障」
