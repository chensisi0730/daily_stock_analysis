# 2026-09-25

## 修复「搜索引擎无结果」（继 2026-09-24 的测试验收）

### 根因：测试脚本构造方式与生产不一致（与 LLM 主通道项同类问题）

- `test_full_system.py::test_search()` 原用**无参 `SearchService()`**。`SearchService.__init__` 的 keys 默认全为 `None`，因此只注册了默认的 SearXNG（`searxng_public_instances_enabled` 默认 True）；SearXNG 公共实例拉不到 → 恒空 → 误报"搜索不可用"。
- 生产路径（`main.py:852`、`src/core/pipeline.py:108`、工厂 `get_search_service()`）都会显式注入 `config.tavily_api_keys` / `anspire_api_keys` / `serpapi_keys` 等。
- **修复**：`test_full_system.py` 改用 `from src.search_service import get_search_service`，并在通过详情里带上实际命中的 provider。
- **验证**：`py_compile` 通过；`test_search()` 单独跑通过，返回 3 条真实新闻（NVDA 董事售出 136.6 万股 / 130 亿美元收购 Hugging Face），实际命中 **Tavily，3.9s**。

### 附带发现

- **Anspire key 已失效**：`可用余额不足，当前可用免费额度 0.00，充值余额 -0.05`，provider 侧将该 key 标记为"已被永久禁用"。搜索会自动降级到 Tavily，不影响功能，但建议充值或从 `.env` 移除以免每次打印告警。
- 代理：本机 Clash Verge / cc-switch 在 **7897 与 7899** 均监听，`.env` 的 `PROXY_PORT=7897` 是对的，但 `USE_PROXY=false`（未启用）。实测 Tavily / SerpAPI **直连即可通**（200），走 7897 代理反而 ProxyError；SearXNG 公共实例直连超时。结论：本项目搜索无需开代理。

### 排查此类问题的通用姿势

`test_full_system.py` 的失败项先区分两类：
1. 真故障（网络/额度/配置非法）
2. **脚本构造方式与生产不一致导致的误报** —— 已出现两次：LLM 主通道不走 Router、搜索不注入 keys。
判断方法：直接按生产路径（Router / `get_search_service()`）复现一次，能通就是脚本问题。
